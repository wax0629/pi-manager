# Pi Manager 可交互原型演示指南

这份文档用于帮助开发团队、设计师和利益相关者理解当前运行在 `web` 目录下的 React 可交互原型，以及已经落地的首条真实交互链路。

## 1. 启动原型

在项目根目录下执行以下命令（如果您当前已经在 `web` 目录，可省略第一步）：
```bash
cd web
npm run dev
```
随后在浏览器中访问 `http://localhost:5173/` 即可。

## 2. 设计语言与风格
原型深度借鉴了 **Vercel** 与 **Linear** 的视觉美学：
- **无色相中性灰 (True Neutrals)**：极纯的黑白灰背景 (`#FAFAFA` / `#0A0A0A`)，排除任何引起视觉干扰的色偏。
- **高对比 (High Contrast)**：按钮与交互控件强调极致的黑白对比。
- **克制的点缀**：摒弃大面积的彩色块或粗糙的边框，以极细的 `1px` 边框和 `10px` 药丸形 Badge 传达状态信息，仅在关键的“焦点操作”（如未保存状态、激活的开关）上使用主色调。
- **精致的光影**：扁平化布局配合微弱的 `Hover` 上浮和扩散阴影。

## 3. 核心用户故事体验路径

请按照以下顺序在原型中进行点击，以体验完整的“配置修改 -> 确认 -> 部署”逻辑闭环。

### 步骤一：触发草稿状态 (Dirty State)
1. 默认进入 **供应商与账号** 页面。
2. 页面先从 `GET /api/state` 读取真实的 provider、模型和当前路由。
3. 供应商卡片只用于查看接入状态、刷新和删除，不负责选择实际使用的模型。
4. **观察点**：顶部只读显示当前 provider/model；配置 revision 与已应用 revision 不一致时，`部署变更` 才会启用。

### 步骤二：通过向导新增供应商 (Wizard)
1. 点击页面右上角的 `新增供应商` 按钮。
2. 在表单中填写名称、可选 Provider ID、Base URL、至少一个模型 ID 和可选 API Key。
3. 点击 `保存为候选配置`。
4. **观察点**：新增卡片来自后端响应，API Key 只显示配置状态；顶部出现未应用修改，等待部署。

### 步骤三：管理模型目录 (Model Catalog)
1. 点击左侧导航栏的 **模型资源库**。
2. 在这里可以看到所有 `Provider` 底下模型的全局只读视图（包含 Capability、Thinking 等级和来源）。
3. 切换到 **默认模型**，选择已连接的 Provider、Model 和该模型支持的 Thinking 等级。
4. 切换到 **循环列表**，把想保留的模型加入列表并调整顺序。
5. 点击 `保存为候选配置`。这一步只更新 Manager 的候选 revision，不会立即改变正在运行的 Pi。

### 步骤四：统一部署与模拟注入 (Deploy Flow)
1. 切换到 **环境 Profiles**。
2. 在这里可以看到候选配置、已应用配置、profile 目录和注入路径。
3. 点击 `应用配置`、`应用并启动`、`停止 Pi` 或 `回滚到上次应用`。
4. **观察点**：应用后 `appliedRevision` 与候选 revision 一致；回滚后页面会恢复到上次成功应用的快照；启动和停止会使用当前受控 profile 的进程追踪信息。

## 4. 后续开发建议

当前页面已经通过 `web/src/api.ts` 接入本地 Manager API，默认模型路由、循环列表、thinking 映射和 Profile 应用/回滚都已可操作；停止 Pi 和更完整的进程生命周期仍在后续切片中。

1. **状态管理**：由于有“未保存更改”的机制存在，建议引入 `Zustand` 或 `Redux` 作为单一事实来源 (Single Source of Truth)，来管理底层实际配置与前端草稿配置之间的 Diff 比对。
2. **API 设计**：继续扩展已有业务接口：
   - `GET /api/state`：读取 Manager 持久化状态和运行摘要。
   - `POST /api/providers`：保存 provider 元数据和凭据引用。
   - `POST /api/apply`：生成隔离 profile；后续再接入完整 diff、验证和回滚。
3. **轮询机制**：可以为每个卡片状态增加 SSE (Server-Sent Events) 或 WebSocket 推送，当真正的后台守护进程（Pi Engine）掉线或状态变更时，实时反馈到 UI 的徽章上。
