本文档用于指导 Pi Manager 第一版可点击原型。重点定义页面、功能元素、状态、
交互和跳转，不规定最终视觉风格、颜色、字体、插图或动效。

## 2. 原型目标

原型需要验证用户是否能够理解并完成以下任务：

1. 识别当前 Pi 环境和正在编辑的 profile；
2. 使用 Pi 原生方式连接订阅或 API provider；
3. 添加一个 URL + API Key 的第三方中转；
4. 在统一模型目录中区分不同模型来源；
5. 编辑完整模型目录策略和 Ctrl+P 循环列表；
6. 设置默认模型和 thinking 映射；
7. 查看配置变化，应用 profile 并启动 Pi；
8. 在应用失败后查看原因并回滚。

原型验证的是信息结构和操作流程，不验证真实认证、文件写入、模型请求或进程
管理。

## 3. 原型范围

### 3.1 原型必须包含

- 首次启动和 Pi 环境检测；
- 总览；
- 供应商与账号；
- Pi 原生登录流程；
- 添加和编辑自定义中转；
- 模型管理；
- 循环列表排序；
- thinking 映射编辑；
- Profile 与应用；
- 配置变更预览；
- 应用成功、应用失败和回滚；
- 诊断页面；
- 加载、空、不可用、错误和未保存状态。

### 3.2 原型不包含

- 真实 OAuth 跳转；
- 真实 API key 输入和保存；
- 真实 Pi 进程、终端或 RPC；
- 真实网络请求和端口管理；
- Antigravity adapter；
- 账号池、配额轮换和自动 fallback；
- 移动端界面；
- 完整视觉规范和设计系统。

## 5. 全局信息结构

### 5.1 一级导航

| 导航项 | 作用 |
| --- | --- |
| 总览 | 查看当前运行状态、配置状态和主要操作 |
| 供应商与账号 | 管理原生 provider、订阅、API key 和第三方中转 |
| 模型管理 | 管理完整目录、循环列表、默认模型和 thinking |
| Profile 与应用 | 管理 profile、查看变更并应用到 Pi |
| 诊断 | 查看 Pi 能力、认证、配置和运行错误 |

### 5.2 全局顶部区域

所有一级页面都包含以下元素：

| 元素 | 内容与行为 |
| --- | --- |
| 当前 Profile 选择器 | 显示当前 profile；可切换；有未保存修改时先提示 |
| 目标项目 | 显示当前项目名称或路径；点击进入 Profile 与应用页 |
| Pi 状态 | 已运行、已停止、未检测到、运行异常 |
| 配置状态 | 已同步、存在未应用修改、应用失败 |
| 应用按钮 | 有合法修改时可用；点击打开配置变更预览 |

### 5.3 全局状态概念

用户界面必须区分三套状态：

| 状态 | 含义 | 页面表现 |
| --- | --- | --- |
| 候选配置 | 用户正在编辑的内容 | 显示“未应用修改” |
| 已应用配置 | 最近一次成功生成的 profile | 显示 revision 和应用时间 |
| 运行配置 | 当前 Pi 进程实际使用的配置 | 显示当前 provider/model/thinking |

候选配置与已应用配置不同，不代表 Pi 已经改变。只有完成“应用”并验证后，页面
才能把候选配置标记为已应用。

## 6. 页面 P00：首次启动与环境检测

### 6.1 页面目的

确认 Pi 是否可用，并创建第一个 Manager profile。该页面只在首次启动或无法读取
任何 profile 时出现。

### 6.2 页面元素

| 区域 | 元素 | 行为 |
| --- | --- | --- |
| 环境检测 | Pi 可执行文件 | 自动检测，也可手工选择路径 |
| 环境检测 | Pi 版本 | 检测成功后显示 |
| 环境检测 | 能力检查列表 | Profile、auth、models、RPC/SDK、extension |
| 项目选择 | 目标项目路径 | 选择一个本地项目目录 |
| Profile | Profile 名称 | 默认“日常开发”，允许修改 |
| 导入选项 | 从现有 Pi 配置读取 | 只读扫描；原型中进入导入预览 |
| 主操作 | 创建 Profile | 所有必填项合法后可用 |

### 6.3 能力检查状态

- 检测中；
- 支持；
- 不支持；
- 未验证；
- 检测失败。

每个失败项需要提供“重新检测”或“选择其他 Pi 路径”，不能只有错误图标。

### 6.4 跳转

- 创建成功：进入“总览”；
- Pi 未安装：停留当前页，可打开安装说明；
- 导入现有配置：打开“配置导入预览”弹窗；
- 取消导入：返回首次启动页，已填写内容保留。

## 7. 页面 P01：总览

### 7.1 页面目的

回答四个问题：Pi 是否可用、当前使用什么模型、配置是否已同步、下一步能做什么。

### 7.2 页面元素

#### 当前运行

| 元素 | 内容 | 操作 |
| --- | --- | --- |
| Pi 运行状态 | 已运行 / 已停止 / 异常 | 点击进入诊断 |
| 当前 Provider | 完整 provider 名称 | 点击进入对应供应商详情 |
| 当前 Model | `providerId/modelId` | 点击进入模型详情 |
| 当前 Thinking | 当前 Pi 标准等级 | 点击打开 thinking 映射抽屉 |
| 启动/停止按钮 | 根据运行状态切换 | 启动或停止 Manager 管理的 Pi |

#### 配置状态

| 元素 | 内容 | 操作 |
| --- | --- | --- |
| 当前 Profile | 名称、目标项目 | 点击进入 Profile 与应用 |
| 已应用 Revision | 编号、时间 | 点击查看应用报告 |
| 未应用修改 | 修改数量和分类 | 点击查看配置变更预览 |
| 回滚可用性 | 上一成功 revision | 点击打开回滚确认 |

#### 供应商摘要

- 已连接原生订阅数量；
- 已配置 API provider 数量；
- 需要重新授权数量；
- 配置错误数量；
- “管理供应商”入口。

#### 模型摘要

- effective catalog 模型数量；
- 当前可用模型数量；
- 循环列表模型数量；
- thinking 映射待确认数量；
- “管理模型”入口。

### 7.3 页面状态

**正常状态**

显示当前运行和已应用配置，可直接启动或停止 Pi。

**有未应用修改**

顶部和配置状态区同时显示“有 N 项未应用修改”；启动按钮改为“应用并启动”。

**Pi 未运行**

保留上一次运行配置，并明确标注它不是当前运行状态。

**应用失败**

显示失败摘要、“查看错误”和“恢复上一版本”。

**无可用 provider**

显示下一步操作“连接原生账号”或“添加自定义中转”。

## 8. 页面 P02：供应商与账号

### 8.1 页面目的

统一管理 Pi 原生 provider 和用户自定义 provider，同时保持两者认证方式的差异。

### 8.2 页面结构

页面分为两个切换视图：

- Pi 原生；
- 自定义中转。

顶部提供搜索、状态筛选和“添加自定义中转”。

### 8.3 Pi 原生列表元素

每一项展示：

| 元素 | 说明 |
| --- | --- |
| Provider 名称 | 例如 OpenAI Codex、Anthropic |
| Provider ID | Pi 实际标识 |
| 支持认证 | 订阅 OAuth、API key 或两者 |
| 当前认证 | 当前 profile 正在使用的认证方式 |
| 状态 | 已登录、未登录、即将过期、需要重新授权、错误 |
| 模型数量 | discovered 和 available 数量 |
| 操作 | 登录、检查状态、重新授权、退出、查看详情 |

### 8.4 自定义中转列表元素

每一项展示：

| 元素 | 说明 |
| --- | --- |
| 显示名称 | 用户定义名称 |
| Provider ID | 用于完整模型引用 |
| Base URL | 脱敏显示，保留 host 和路径 |
| API 类型 | OpenAI Completions、Responses 等 |
| 凭据状态 | 已配置、未配置、错误 |
| 模型数量 | 已配置 / 可用数量 |
| 启用开关 | 影响候选配置，不立即影响运行中的 Pi |
| 操作 | 测试、编辑、复制、删除 |

### 8.5 列表状态

- 加载中：显示列表骨架和扫描说明；
- 空状态：显示“还没有自定义中转”和添加入口；
- 无搜索结果：保留筛选器并提供清除；
- Provider 错误：在对应行显示原因和修复入口；
- Profile 未选择：列表只读，提示先选择 profile。

## 9. 弹窗 D01：Pi 原生登录

### 9.1 触发方式

在 Pi 原生 provider 行点击“登录”或“重新授权”。

### 9.2 第一步：选择认证方式

当 provider 同时支持订阅和 API key 时，展示两个选项：

- 使用订阅登录；
- 使用 API key。

只支持一种认证方式时直接进入下一步。

### 9.3 第二步：原生登录过程

原型使用“Pi 登录终端区域”模拟真实 PTY，包含：

| 元素 | 行为 |
| --- | --- |
| Provider 名称 | 明确当前登录目标 |
| Profile 名称 | 明确凭据写入哪个 profile |
| 终端输出区 | 展示模拟的 `/login <provider>` 输出 |
| 打开浏览器 | 模拟打开 OAuth 页面 |
| 粘贴授权结果 | 仅用于需要手工回填的 mock 流程 |
| 取消 | 终止登录并返回供应商页 |

API key 模式下，输入框默认隐藏内容，提供显示/隐藏和“保存到系统凭据库”选项。

### 9.4 登录结果

**成功**

- 显示 provider 和登录方式；
- 显示“已写入当前 profile”；
- 提供“查看可用模型”和“完成”。

**取消**

- 不改变原有认证状态；
- 返回供应商列表。

**失败**

- 显示错误类型；
- 提供重试、切换认证方式和查看诊断；
- 不显示任何 token 或完整 API key。

## 10. 流程 W01：添加自定义中转

### 10.1 流程结构

使用分步流程，避免把 provider 和所有模型参数堆在一个表单中：

1. 基本连接；
2. 凭据与测试；
3. 模型；
4. 确认保存。

用户可以返回上一步，已填写内容保留。关闭时若有修改，显示放弃确认。

### 10.2 第一步：基本连接

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 显示名称 | 文本输入 | 必填，可重复但不建议 |
| Provider ID | 文本输入 | 必填、profile 内唯一、保存后默认不可修改 |
| Base URL | URL 输入 | 必填，默认 HTTPS |
| API 类型 | 单选/下拉 | 默认 `openai-completions` |
| 自定义 Headers | 可添加键值行 | 可选，敏感值可标记为 secret |

页面即时显示模型完整引用示例：`providerId/modelId`。

### 10.3 第二步：凭据与测试

| 元素 | 行为 |
| --- | --- |
| API Key | 密码输入；原型只接受 mock 值 |
| 保存位置 | 默认系统凭据库；profile auth 作为兼容选项 |
| 测试方式 | 测试认证和模型端点 |
| 测试按钮 | 进入测试中、成功或失败状态 |
| 跳过测试 | 允许继续，但 provider 标记为未验证 |

测试结果至少包含：

- URL 是否可访问；
- 认证是否被接受；
- 是否返回模型列表；
- API 类型是否可能不兼容；
- 错误摘要和建议操作。

### 10.4 第三步：模型

提供两种添加方式：

- 从测试返回的模型中选择；
- 手工添加模型。

模型表格包含：

| 字段 | 行为 |
| --- | --- |
| Model ID | 必填；provider 内唯一 |
| 显示名称 | 默认等于 Model ID，可修改 |
| 输入能力 | 文本必选，图片可选 |
| Reasoning | 开关 |
| Context Window | 数字输入 |
| Max Output Tokens | 数字输入 |
| Thinking | 显示支持等级摘要，点击打开映射编辑器 |
| 更多兼容设置 | 折叠区域，非首要操作 |

至少添加一个模型后才能进入下一步。模型行支持复制、编辑和删除。

### 10.5 第四步：确认保存

展示：

- Provider 完整信息摘要；
- 凭据保存位置和状态，不展示 key；
- 模型数量与模型引用；
- 是否已通过连接测试；
- 将产生的候选配置变化；
- “保存为候选配置”主操作。

保存后进入该 provider 详情页，并显示全局“未应用修改”。

## 11. 页面 P03：Provider 详情

### 11.1 原生 Provider 详情

包含：

- Provider 基本信息；
- 当前认证方式和状态；
- 登录、重新授权、退出；
- discovered/available 模型列表；
- 完整目录过滤能力：支持、不支持、未验证；
- 最近一次认证检查和模型刷新；
- 进入模型管理的入口。

### 11.2 自定义 Provider 详情

包含：

- 显示名称、Provider ID、Base URL、API 类型；
- 凭据状态和更换凭据；
- 启用开关；
- 测试连接；
- 模型列表及添加模型；
- 生成配置预览；
- 编辑、复制和删除。

Provider ID 修改会影响模型引用、默认模型和循环列表，因此默认只读。用户需要
修改时，使用“复制为新 Provider”，再删除旧项。

## 12. 页面 P04：模型管理

### 12.1 页面目的

在一个页面中完成模型发现、可见性策略、循环列表、默认模型和 thinking 管理。

### 12.2 页面切换视图

- 完整目录；
- 循环列表；
- 默认模型。

三个视图共享同一套候选配置，切换时不丢失修改。

### 12.3 完整目录视图

#### 顶部工具

| 元素 | 行为 |
| --- | --- |
| 搜索 | 匹配显示名、model ID 和完整引用 |
| Provider 筛选 | 单个或全部 provider |
| 来源筛选 | Pi 原生、自定义、Adapter |
| 状态筛选 | 可用、未认证、错误、隐藏 |
| 刷新目录 | 模拟重新读取 effective catalog |

#### 模型表格

| 列 | 内容或操作 |
| --- | --- |
| 模型 | 显示名和 `providerId/modelId` |
| Provider | Provider 名称和来源类型 |
| 可用状态 | 可用、未认证、错误、未验证 |
| 输入 | 文本、图片 |
| Context | context window |
| Reasoning | 支持或不支持 |
| Thinking | 支持等级摘要；点击编辑 |
| 完整目录 | 显示、隐藏或 Pi 不支持精确过滤 |
| 循环列表 | 加入/移除开关 |
| 更多 | 查看详情、设为默认 |

#### 完整目录控制规则

- 自定义 provider：允许显示/隐藏；
- 已验证支持过滤的原生 provider：允许显示/隐藏；
- 不支持过滤的原生 provider：控件不可操作，显示“Pi 原生目录仍可见”；
- 未验证 provider：显示“未验证”，提供查看诊断入口；
- UI 中隐藏不能被描述为已经从 Pi `/model` 删除，除非有验证结果。

### 12.4 循环列表视图

页面分为两个区域：

**已加入循环**

- 按当前 Ctrl+P 顺序展示；
- 支持拖动排序；
- 支持移除；
- 支持设为默认；
- 每项显示完整模型引用和当前 thinking 默认值。

**可加入模型**

- 搜索和 provider 筛选；
- 只展示合法且可用的模型；
- 点击“加入”后进入已加入区域末尾。

列表为空时显示：Pi 将使用自身默认的全部可用模型范围。用户必须明确确认后才能
应用空循环列表。

### 12.5 默认模型视图

包含：

- 默认 Provider 选择；
- 默认 Model 选择；
- 默认 Thinking 选择；
- 模型完整引用；
- 认证状态；
- thinking 支持等级；
- 当前值与已应用值对比；
- “恢复已应用值”。

默认模型必须存在、可用，并且默认 thinking 必须受该模型支持。

## 13. 抽屉 D02：Thinking 映射编辑器

### 13.1 页面目的

让用户明确看到 Pi 标准 thinking 等级如何映射到当前上游模型。

### 13.2 顶部信息

- 模型显示名；
- 完整模型引用；
- Provider；
- Reasoning 状态；
- 映射来源：Pi 内置、供应商文档、请求探测、用户设置。

### 13.3 映射表

每一行对应一个 Pi 等级：

| Pi 等级 | 控件 | 可选状态 |
| --- | --- | --- |
| off | 上游值输入/选择 | 字符串、使用默认、不支持 |
| minimal | 上游值输入/选择 | 字符串、使用默认、不支持 |
| low | 上游值输入/选择 | 字符串、使用默认、不支持 |
| medium | 上游值输入/选择 | 字符串、使用默认、不支持 |
| high | 上游值输入/选择 | 字符串、使用默认、不支持 |
| xhigh | 上游值输入/选择 | 字符串、使用默认、不支持 |
| max | 上游值输入/选择 | 字符串、使用默认、不支持 |

交互规则：

- “不支持”保存为 `null`；
- “使用默认”表示不写该字段；
- 自定义字符串保存为上游实际值；
- `reasoning=false` 时除 `off` 外默认不可用；
- 当前默认 thinking 被改成不支持时，保存前要求选择新的默认等级；
- 提供“恢复 Pi 默认映射”和“复制其他模型映射”。

### 13.4 保存结果

点击“保存映射”只更新候选配置。关闭抽屉后，模型表格更新支持等级摘要，顶部显示
“未应用修改”。

## 14. 页面 P05：Profile 与应用

### 14.1 页面目的

管理 profile、目标项目和配置 revision，并提供统一应用入口。

### 14.2 Profile 列表

每个 profile 展示：

- 名称；
- 目标项目；
- 默认模型；
- Provider 数量；
- 已应用 revision；
- 配置状态；
- Pi 运行状态；
- 切换、复制、重命名和删除。

删除前需要显示该 profile 的凭据引用、运行进程和 revision 影响。当前运行中的
profile 不能直接删除。

### 14.3 当前 Profile 详情

| 区域 | 元素 |
| --- | --- |
| 基本信息 | 名称、目标项目、profile 目录、创建时间 |
| 当前默认 | provider、model、thinking |
| 模型范围 | 完整目录策略数量、循环列表数量 |
| 配置状态 | 候选、已应用、运行配置摘要 |
| Revision | 当前和上一成功 revision |
| 操作 | 查看变更、应用、应用并启动、停止、回滚 |

### 14.4 配置文件摘要

展示将由 Manager 管理的文件，但不要求用户直接编辑：

- `settings.json`；
- `models.json`；
- `auth.json` 状态，不展示内容；
- `manifest.json`；
- 可选 extension；
- 启动参数和环境变量名称，敏感值脱敏。

点击某个文件进入只读配置预览。

## 15. 弹窗 D03：配置变更预览

### 15.1 触发方式

点击全局“应用”、总览“查看修改”或 Profile 页面“查看变更”。

### 15.2 内容结构

#### 变更摘要

- 添加/删除/修改的 provider；
- 登录状态变化；
- 添加/删除/修改的模型；
- 循环列表变化和顺序；
- 默认 provider/model/thinking 变化；
- 将生成、修改或删除的 Manager profile 文件。

#### 分类详情

使用以下分类切换：

- 供应商；
- 模型；
- 循环列表；
- 默认值；
- 文件与启动参数。

每项展示“已应用值 -> 候选值”。密钥和 token 只显示“已配置”“已替换”或
“将删除”。

### 15.3 阻断问题

存在以下情况时，应用按钮不可用：

- 默认模型不存在或不可用；
- 循环列表包含 invalid 模型；
- Provider ID 冲突；
- 必需凭据缺失；
- thinking 默认等级不受支持；
- profile 目录不可写。

每个问题提供跳转到对应页面的“修复”操作。

### 15.4 操作

- 取消：保留候选配置；
- 仅应用：生成 profile，不启动 Pi；
- 应用并启动：生成 profile 并启动/重启 Pi；
- 导出预览：原型中展示脱敏文本，不实际生成文件。

## 16. 页面/弹窗 P06：应用进度与结果

### 16.1 应用进度

按顺序展示步骤：

1. 校验配置；
2. 生成候选 profile；
3. 校验 Pi 模型目录；
4. 写入 profile；
5. 启动或重启 Pi；
6. 读取实际运行状态；
7. 提交 revision。

每一步有等待、成功、失败和跳过状态。当前步骤失败后，后续步骤不能显示成功。

### 16.2 应用成功

展示：

- 新 revision；
- 应用时间；
- 实际 provider/model/thinking；
- 实际 scoped models 数量；
- Pi 是否已启动；
- 查看注入报告；
- 返回总览。

### 16.3 应用失败

原型使用“Company Gateway API 类型不兼容”模拟失败，展示：

- 失败步骤；
- 用户可理解的原因；
- 相关 provider/model；
- 是否已经自动恢复上一 revision；
- 查看诊断；
- 返回修改；
- 手动回滚。

应用失败不能清空候选配置。用户返回修改后，原有输入仍然存在。

### 16.4 回滚结果

展示恢复到的 revision、默认模型、循环列表数量和 Pi 运行状态。回滚成功后，候选
配置仍可选择保留或放弃。

## 17. 页面 P07：诊断

### 17.1 页面目的

集中展示影响认证、模型目录、配置注入和 Pi 运行的技术状态。

### 17.2 诊断分组

#### Pi 环境

- 可执行路径；
- 版本；
- 配置目录能力；
- SDK/RPC；
- extension；
- 重新检测。

#### Profile

- profile 路径；
- 文件存在性和解析状态；
- revision 和 fingerprint；
- 是否检测到项目 `.pi` 资源；
- 配置隔离状态。

#### 认证

- Provider；
- 认证类型；
- 已配置/过期/错误；
- 最后检查时间；
- 重新检查或登录。

#### 模型目录

- discovered/available 数量；
- 目录来源；
- 刷新状态；
- 完整目录过滤能力；
- 无效模型和修复入口。

#### 运行状态

- Pi PID（mock）；
- 启动时间；
- 当前 provider/model/thinking；
- scoped models；
- 最近错误。

### 17.3 日志列表

每条记录只包含：

- 时间；
- 类型；
- providerId；
- modelId；
- 状态；
- 耗时；
- 脱敏错误摘要；
- request ID。

提供级别筛选、关键词搜索、复制单条摘要和导出诊断包。原型中导出操作只显示
“诊断包不包含凭据、prompt 和响应内容”的确认提示。

## 18. 通用弹窗和反馈

### 18.1 未保存修改确认

触发条件：用户切换 profile、关闭窗口或进入首次设置时存在候选修改。

操作：

- 返回继续编辑；
- 放弃候选修改；
- 保存为候选草稿。

### 18.2 删除 Provider 确认

展示受影响内容：

- 模型数量；
- 是否为默认 provider；
- 是否包含默认模型；
- 循环列表中的关联项；
- 使用该 provider 的 profile。

存在引用时不能直接删除，必须先选择替代默认模型或确认移除关联项。

### 18.3 回滚确认

展示当前 revision、目标 revision、将恢复的默认模型和循环列表。明确回滚不会恢复
已经退出的第三方账号或已经在系统凭据库中删除的 key。

### 18.4 操作反馈

- 简短成功操作使用非阻塞提示；
- 需要后续处理的错误使用页面内错误区或弹窗；
- 进行中的认证、测试、刷新和应用必须有持续状态；
- 不能只用颜色表达成功、警告或错误。

## 22. 原型验收标准

原型完成时应满足：

- 五个一级导航均可进入并返回；
- F01-F06 六条流程均可从起点点击到明确结果；
- 用户能区分 Pi 原生 provider 和自定义中转；
- 用户能区分同名模型的不同 provider 来源；
- 用户能理解完整目录和循环列表不是同一配置；
- 用户能看到原生 provider 的目录过滤能力限制；
- thinking 映射支持字符串、默认和不支持三种状态；
- 候选、已应用和运行配置在页面中不会混淆；
- API key、OAuth token 不会在任何页面中完整显示；
- 至少包含一次成功应用和一次失败回滚路径；
- 所有阻断错误都有返回修改或修复入口；
- 原型不依赖真实 Pi、真实账号或真实 API key。
